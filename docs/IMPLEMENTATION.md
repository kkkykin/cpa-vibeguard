# Implementation evidence

The six delivery steps in PLAN.md are complete for the pinned Linux/amd64 target and the observed API boundaries documented below. Final verification was completed on 2026-09-12 against code baseline `312396e`; the acceptance record is at the end of this file.

1. Plugin skeleton, configuration, and entrypoint inventory
   - [x] Strict configuration defaults, types, duplicate members, JSON Pointer syntax, and header conditions (`internal/config`, `internal/document`). Verified with `go test ./internal/document ./internal/config`.
   - [x] Native ABI, four capabilities, lifecycle, bounded request state, and sticky bypass. Verified with `go test -race ./...`, `go vet ./...`, `make build`, and `TestNativeABI`.
   - [x] Unmodified pinned CPA loads and registers the shared library; Chat JSON/SSE bypass round trips and successful-envelope business rejection are verified by `TestHostLifecycle` (including asynchronous capacity release).
   - [x] The actual example Caddy routing is exercised with Caddy v2.10.2: prefix stripping/header injection, removal of a client-supplied skip header on the normal path, JSON/SSE bypass, marker preservation, and unchanged CPA authentication (`TestCaddyPrefixAndHeaderBoundary`).
   - [x] `testdata/entrypoints.json` records 66 unmodified-host cases with actual SourceFormat/ToFormat, request shapes/keys, response shapes, and ordered hook phases. A separate test-only ABI probe observes Chat/legacy, native/compatible protocol matrix, counters, image/video routes, both WebSocket aliases/turns, and paths with no request hooks. Schema 6 payload callbacks omit original requests and history. The probe logs no body/header/identity/session values.
   - [x] `TestHostRPCFaultIsSkipped` injects request-hook RPC errors from a test library and verifies original fixture text reaches the upstream. A successful-envelope Terminate prevents the upstream call and completes with outcome rejected; production business rejection is separately verified by `TestHostLifecycle`.
2. Rule engine
   - [x] Unified TOML/YAML/inline documents, official defaults, field-preserving merges, disable unions, literal variable binding, bounded compilation cache, dynamic allowlists, and exact Gitleaks spans (`internal/rules`). `go test -race ./internal/rules ./internal/plugin`, `go vet ./...`, native build, and host integration tests pass.
   - [x] Regressions for capture-group occurrence selection, UTF-8/CRLF/multiline positions, crossing spans, gitleaks:allow comments, generic-rule suppression, invalid/disabled rules, and immutable concurrent bindings.
3. Requests and ordinary responses
   - [x] Transactional random-marker store and exact restoration (`internal/token`): 128-bit random IDs, stable concurrent reuse, scope isolation, rollback, bounded entries/bytes, idle TTL, active leases, and single-pass restoration. Verified with `go test -race ./internal/token`.
   - [x] SourceFormat adapters for Chat/legacy, Responses/compact, Claude/count, Gemini/count, Interactions, Codex/Antigravity, image/video, and SDK search text. Paired fixtures are in `testdata/protocols.json`; selected-field, opaque-data, precision, JSON tool codec, and hint tests pass.
   - [x] Responses `text.format` JSON-schema descriptions/titles are selected in requests, ordinary echoes, and stream snapshots. Schema names, property names, enum values and constraints remain unchanged; the paired schema fixture also runs through the C ABI.
   - [x] Request scope integration, atomic request-error rollback, sticky retries, ordinary-response restoration, and response degradation. All paired fixtures pass through the real C ABI; unmodified host Chat and legacy Completions redact before upstream and restore after execution (`TestHostProtectedChatAndLegacy`).
   - [x] Ordinary response restoration budgets selected output fields before copying original text; repeated-marker expansion stops on the first overflowing append and preserves the original response transactionally (`TestRewriteStopsBeforeLargeExpansion`, `TestOrdinaryResponseExpansionIsBoundedAndTransactional`). Final encoded JSON and tool limits are also enforced.
   - [x] Real CPA native Claude, Gemini, Interactions, Responses/Codex, both Codex aliases, compact and compatible compact; representative Chat→Gemini, Claude→Chat, Responses→Chat, and Interactions→Gemini execution. `TestHostNativeAndCrossProtocolMatrix` checks masked upstream fields and restored client fields.
   - [x] Gemini countTokens, Claude first-party HTTPS count_tokens (local CONNECT/TLS fixture), and Claude custom-gateway local estimation. Both counters consume the protected input (`TestHostClaudeNativeCountAndLocalCount`).
   - [x] Multipart image prompt handling preserves uploaded file bytes and filenames, validates duplicate/encoded text fields, and keeps header/metadata session sources available. JSON normalized by CPA still uses the JSON adapter.
   - [x] `TestHostMediaAndSearchBoundaries` exercises compatible/xAI/Codex image generation and JSON/multipart editing, image Responses execution, xAI video generation/edit/extension and Sora compatibility, session-bound polling, and unchanged binary downloads. The download first executes a hooked JSON metadata poll; the actual media transfer is outside these text adapters. xAI's synthetic image SSE is generated after the ordinary response hook and omits revised_prompt in the host.
   - [x] Both Alpha Search HTTP aliases demonstrably bypass these hooks and receive the original fixture query. The SDK search adapter does not imply HTTP-route coverage. The human-readable inventory and limits are in [COVERAGE.md](COVERAGE.md).
4. Sessions and multi-turn requests
   - [x] Ordered profiles and header/JSON/metadata sources, trusted identity/namespace isolation, leases, history reference registration, generation-aware expiry, capacity, and retry idempotence (`internal/session`, plugin/session tests).
   - [x] Unchanged history prefixes remain stable across source switches, concurrent requests, and rule-disable reconfiguration. Real CPA authenticated multi-turn prefix stability passes `TestHostSessionHistoricalPrefix`; no claim is made about real upstream cache hits.
   - [x] Real CPA retries a failed credential with byte-identical protected input and one hint in JSON and streaming execution; the probe sees one before hook and two after hooks (`TestHostCredentialRetryKeepsProtectedBody`). Twelve simultaneously active requests share markers within each of two sessions and remain isolated across sessions (`TestHostConcurrentSessionMarkers`).
5. Streaming and WebSocket
   - [x] Bounded text tails, incremental tool JSON values (keys preserved), and SSE/JSON/array framing. `go test -race ./internal/restore` covers every marker/SSE split, UTF-8/escapes, normal and abnormal tails, duplicate tool keys, and buffer limits.
   - [x] CPA record completion uses incremental SSE data-only balance tracking, including metadata lines and escaped strings. The allocation regression rejects repeated reparsing of 16 KiB of byte-fragmented closing braces; 4 KiB/64 KiB framing benchmarks scale with input length.
   - [x] Request-owned stream hook for Chat, Responses/Codex, Claude, Gemini/Antigravity, and Interactions: independent fields, tool deltas, snapshot restoration, terminal flushing, response ID registration, one-time degradation, and abort cleanup. `go test -race ./internal/restore ./internal/plugin ./internal/protocol`, vet, native build, and integration pass. Five actual C ABI stream fixtures are recorded in `testdata/streams.json`.
   - [x] Real CPA Chat/legacy streams cover every marker split (49 positions), parallel choices, byte-sized tool argument deltas, usage, normal partial tails, and abnormal EOF (`TestHostProtectedChatStreamsEverySplit`, `TestHostStreamToolsAndNormalPartialTail`).
   - [x] Native Claude/Gemini/Interactions/Responses streams and representative compatible streams pass all 49 marker split positions in the unmodified host. CPA's newline-free SSE data/event records, Interactions status/signature events, and echoed Responses tool descriptions have regression tests.
   - [x] `TestHostResponsesWebSocketNativeAndFallback` exercises both aliases, two text/tool turns per connection, stable execution-session markers, connection isolation, and native WebSocket versus configured HTTP execution. CPA rejects cross-connection history with `previous_response_not_found` before the plugin.
   - [x] HTTP cancellation at four partial-marker positions and WebSocket disconnect release request capacity (`TestHostHTTPStreamCancellation`, `TestHostWebSocketDisconnectReleasesRequest`). On the pinned host, both native WebSocket and HTTP fallback retain an active lease during a silent stream until another write, keepalive, or upstream completion reveals the disconnected socket. After fixing startup readiness, the test explicitly observes that boundary in both modes, triggers progress writes, and verifies actual upstream cancellation/cleanup without treating a fixture read timeout as cancellation.
   - [x] Normal partial text tails reach both native and HTTP-backed WebSocket clients before done events (`TestHostWebSocketNormalPartialTail`). The native bare-JSON hook can emit an SSE record group accepted by CPA for this terminal flush. Synthesized Responses events receive sequence numbers and later events are shifted without losing integer precision; overflow is rejected.
6. Release verification and documentation
   - [x] [README](../README.md), [CONFIGURATION.md](CONFIGURATION.md), [OPERATIONS.md](OPERATIONS.md), and [COVERAGE.md](COVERAGE.md) document installation, pinned compatibility, actual defaults and resource accounting, rules/variables/allowlists, sessions/cache stability, Caddy bypass, normal/abnormal tails, degradation and host RPC boundaries, rejected reconfiguration, and versioned-library replacement. Twelve documented YAML/example configurations were registered and exercised through the real C ABI with synthetic environment/header values; local document links and the Caddy configuration were validated.
   - [x] `make bench` measures custom/official rule scanning, dynamic-binding cache hits/misses, split-marker restoration, 256/4096-chunk streams, tool JSON, and byte-fragmented SSE records. [BENCHMARKS.md](BENCHMARKS.md) records Go/CPU/command, actual results, and the distinction between cumulative allocations, retained-state accounting, and unmeasured process RSS.
   - [x] Real CPA config writes exercise rejected updates, successful rule disable/re-enable, compatible session-source changes, and an active stream retaining its old event limit/mapping (`TestHostConfigurationSnapshots`). CPA would detach hooks on a reconfigure RPC error; the plugin instead reports `configuration_error` in a successful registration and logs a value-free diagnostic while keeping the previous config. Initial registration still fails on invalid config. Native ABI and unit tests cover this distinction and quiesce/reactivation.
   - [x] `TestHostRestartAndBinaryReplacement` verifies response-ID continuation before restart/replacement, rejection of stale references afterwards, fresh markers and unchanged unknown old markers. Versioned libraries are installed by atomic rename in a temporary plugin directory after model responses finish. A failed library load exercises CPA's quiesce/reconfigure rollback. The pinned config watcher needs an in-place config write; replacing only the same library pathname does not trigger a new instance.
   - [x] Full-suite execution exposed CPA's startup interval where `/healthz` responds before the initial watcher reload replaces executors and closes early WebSockets. The test harness now waits for this start's watcher-ready log and HTTP health; log offsets prevent stale readiness after restart. The native/fallback WebSocket and restart/replacement tests pass five repeated runs with this readiness condition.
   - [x] Full tests, race, vet, shared-library/host tests, reconfiguration/restart/replacement, benchmarks, and observed coverage matrix. The final complete host suite passed after fixing startup readiness and explicitly verifying the silent-stream disconnect boundary in both WebSocket execution modes.

The build produced `dist/cpa-vibeguard.so` and `dist/cpa-vibeguard.h`; integration scripts built `bin/cpa-host` from the pinned module and `bin/caddy` v2.10.2. These generated artifacts are intentionally ignored by Git. The host and shared library use the normal build; `make check` instruments the Go core directly for race detection, and the integration race command instruments the Go test process, not those separately built processes/libraries.

Committed evidence includes 15 paired protocol fixtures, five stream fixtures, and 66 observed entrypoint cases. The supported scope remains that in [COVERAGE.md](COVERAGE.md): Alpha Search HTTP routes bypass these hooks, media payloads remain opaque, SDK wrapper fixtures do not imply blanket provider coverage, and Realtime/Live plus the full cachedContent lifecycle are not claimed. Host RPC faults can bypass the plugin; both WebSocket upstream modes can retain an active lease during a silent disconnected stream until the host observes the disconnect. These are recorded host/API boundaries, not pending host modifications.
